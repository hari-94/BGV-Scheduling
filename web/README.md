# web/ — BGV Scheduling on Cloudflare

The Cloudflare side of the suite: a Worker that answers `/api/*`, static pages
in `public/`, and the D1 database's migrations. It replaces the Streamlit
screens page by page while Streamlit stays live
(`docs/CLOUDFLARE_MIGRATION.md`); the design is in `docs/SYSTEM_REVIEW.md` and
the database in `docs/DATA_MODEL.md`.

Live at https://bgv.bgvgrandtimber.workers.dev (Worker `bgv`, D1 `bgv`).
Generate (OR-Tools) and Excel roster parsing stay in Python; HotSOS, SSRS,
SharePoint and Teams stay with the office PC agent.

## Layout

| Path | What |
|---|---|
| `src/app.ts` | the API: middleware, routes, the one error shape |
| `src/auth/` | sign-in (challenge → derived key), sessions, permissions |
| `src/health/` | `/api/health` |
| `src/jobs/` | scheduled work (nightly retention) |
| `src/lib/` | clock, crypto, HTTP errors and validation, structured logs, same-origin guard |
| `migrations/` | D1 schema, applied in order (`0001` v1 copy, `0002` schema v2) |
| `tools/copy_from_supabase.py` | copies Supabase into D1's v1 tables and verifies |
| `test/` | Vitest inside the Workers runtime, on a fresh local D1 |
| `worker-configuration.d.ts` | binding types, generated by `npm run types` — don't edit |

## Working on it

```bash
npm ci
cp .dev.vars.example .dev.vars   # local secrets for dev, types and tests
npm run check                    # lint, type-check, tests — what CI runs
npm run dev                      # local Worker at http://localhost:8787
```

After changing `wrangler.jsonc`, run `npm run types` and commit the result
(CI fails if it is stale).

## Database

```bash
npm run db:migrate:local         # apply new migrations to the local D1
npm run db:migrate:remote        # ... to the live D1 (at night: see the plan)
npx wrangler d1 execute bgv --remote --command "EXPLAIN QUERY PLAN ..."
```

A migration is never edited once applied; a change is a new numbered file.

## Deploying

`npm run deploy`, signed in once per PC with `npx wrangler login` as the
suite's Cloudflare account. Secrets are set once with
`npx wrangler secret put <NAME>`:

| Secret | What |
|---|---|
| `CHALLENGE_SECRET` | makes the sign-in decoy for unknown usernames stable |

Every deploy is a version; `npx wrangler rollback` returns to the previous one.

## Conventions

TypeScript `strict` with no `any`; Biome for lint and format; every request
body validated with zod (`readJson`); errors thrown as `HttpError` and returned
as `{ error: { code, message } }`; logs as one JSON object per line (`log`).
Dependency versions pinned, each at least two weeks old when chosen.
